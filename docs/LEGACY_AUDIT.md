# Implementation audit — 10 October 2026

## Scope

Reviewed the local four-survivor build, world routes, lighting, animation, practice bots, loading failures, resource disposal, duplicate/unused code and source licences. Earlier simulation, network, persistence, wallet and reward findings are retained below. This pass changes room capacity and practice behavior; rewards remain off. No commit or public deployment was made.

## Findings addressed

- Inputs are bounded, typed, sequence-checked and rate-limited. Clients never send positions or outcomes. HTTP bodies, origins, room counts, spectator capacity and event/history buffers are bounded.
- Each player snapshot is built from an explicit whitelist. Hidden opponent coordinates, history, input and locker occupancy are excluded. Only the player's own private skill/cooldown data is included. Spectators receive an aged buffer, including on initial sync and at match end.
- Queue-only matches need an unguessable internal creation key and room-bound, expiring, single-use tickets. Wallet signatures are verified on the server; a client-supplied holder flag is ignored. Holder RPC failures remove priority rather than inventing a balance. External requests default off.
- Only one live match is claimed. Ready checks retain assigned roles, time out, and move decliners back. Holder priority cannot repeatedly skip a non-holder. Watch rooms cap at 64 clients and four rooms per process.
- Interrupted inputs stop movement and interactions. Doors, collisions, pallet blocking, interaction distances and facing are server-owned. Skill presses use server receipt time with a bounded latency allowance. Attack rewind is capped. Repeated locker-entry holds no longer immediately exit again.
- Prediction reuses the shared movement/physics helpers, respects lockers and pallets, replays only unacknowledged inputs and never mutates a received snapshot. Reconnect sequences continue above the server acknowledgement.
- Reconnection works even in the first five seconds after joining; the SDK's default minimum uptime was removed. A killer forfeit resolves the match and awards survivor escape points. Final states cannot be changed by a later leave.
- SQL statements are parameterized. Result inserts are atomic and deduplicated by match/wallet. Leaderboard data is aggregated in one query with an index. There are no database calls in simulation ticks except a bounded final-result retry. Failed writes retry at most once per second.
- Replaced primitive characters with textured skinned models, including Aaron Neal’s sculpted creature. Static architecture is batched by material, downloaded scenery is instanced, and repeated PBR maps share texture objects. Rapier stays in a separate chunk. Camera obstruction uses rendered geometry and BVH raycasts.
- Checked unused imports through TypeScript/ESLint and reviewed helpers, duplicate movement/pallet rules, resource disposal, timers and listener cleanup. Match changes remove old actor/pallet instances; skeleton resources and scene resources are disposed. Settings loaded from storage are validated and clamped. Wallet public-key byte conversion was corrected after a browser failure.
- Locker candidates and survivor spawn order are seeded per match. The renderer receives the same eight active locker locations as the server. Candidate entrances are checked against colliders and competing prompts. A results-table overflow at 720p was fixed; browser checks now include child rows and buttons inside the results panel.
- Holder cosmetics are granted from server-verified balances, never client flags. The client uses a shared cleanup helper when moving between matches, queues and spectating. Loading tips, result actions and first-run graphics sampling are included.
- Rewards default off and make no external calls. The CLUMSY Postgres ownership and transfer-reconciliation patterns are adapted for nightly top-survivor and top-killer rewards, without deposits, paid entry or pots. Test/live ledger slots are isolated. Signed bytes and signatures are durable before any broadcast; uncertain transfers reuse the same bytes, and replacements require finalized expiry plus a second historical status lookup. A failed ledger write poisons the worker until restart. Recovery tests cover ownership loss during signing and after durable signing, crashes, uncertain RPC acceptance and post-ack local write failure. Real Postgres tests terminate the owning connection and verify exclusion/recovery.

- Packaged server smoke testing caught and fixed tsup stripping the required `node:` prefix from SQLite. A dedicated config preserves builtin imports and targets Node 26. The Jayson override removes its vulnerable streaming parser; the browser RPC interface was compared and tested against a local fake provider. `npm audit --omit=dev` reports zero vulnerabilities.

## Graphics audit findings addressed

- Converted quantized glTF attributes to float before baking transforms; this fixes overflow that distorted scanned geometry. A regression test covers normalized integer positions.
- Normalize fallen logs by their longest dimension instead of height; the previous rule created camera-blocking oversized geometry. Select one tree/grass/bush variant before export and simplify by asset budget.
- Wait for characters, scenery, surface textures and environment lighting before enabling entry. Failed downloads show a reload error. Menu actors are created after assets finish, so placeholders cannot persist.
- Use a separate 4K sky panorama and 1K HDR reflection map; remove the clipped procedural sky sphere. Keep depth of field out of live gameplay and character previews.
- Map public lunge/wipe/stunned actions to the imported attack/stun clips. Correct first-person hit/miss timing, exclude torso/head triangles from the view model and anchor the forearms below the camera. Regression tests cover camera movement, repeated swings, both cooldowns and animation selection.
- Add soft character contact shadows, a camera-following moon shadow region, blended mud paths, fire embers and High/Ultra ambient occlusion without changing collision geometry or server rules.
- Dispose the PMREM render target, shader-only terrain textures, per-instance charms/contact shadows and cloned skeletons. Reuse loaded geometry/materials, the geometry-baking helper and the existing animation mixer. Remove the unused procedural character/sky modules and obsolete shrub/denim exports.
- Verify free-use terms, include Aaron Neal’s required attribution in shipped credits, preserve Poly Haven authors/source links, and document Quaternius CC0 sources. Pin killer archive hashes and extract only named model/image files. No imported script, Unreal AI or executable is run.
- TypeScript now includes the asset-conversion scripts; nullable animation channels and colour tuple types were corrected. TypeScript and ESLint check unused imports/code. Reviewed new rendering helpers for duplicate work, cleanup and error propagation. No database queries, API endpoints, authentication, recovery or lease state machines were changed. Production dependency audit reports zero known vulnerabilities.

## Limits that remain

This is a playable local implementation, not certification that every production requirement is complete. The killer has 55,175 triangles, 17 clips and 2K skin textures. Survivors have 18,812–22,962 triangles and 33 clips each; their free clothing assets remain stylized. Thirty original synthesized scream WAVs are positional; they are not human actor recordings. The world pass adds 26 environmental clips (3,166,156 bytes) and two scanned props. Colour grading, menu depth of field and height fog are implemented. Textures use WebP rather than KTX2. Environmental audio and music now include credited CC0 recordings; wall muffling and reverb are inexpensive approximations, not acoustic simulation. The scene is substantially more detailed, but this is not a claim of AAA production quality or broad hardware acceptance. The local map and chase balance need human playtesting.

SQLite persistence and a real, isolated local Postgres instance are exercised, including durable reads after reconnecting and duplicate result insertion. External wallet prompts, actual holder balances and Mobula market/chart data have not been exercised; market data remains unavailable. The optional adapted CLUMSY reward ledger is tested locally but remains off; no real-money transfer was attempted. In-progress matches and score writes that have not yet committed do not survive process termination; production deployment and broad device performance acceptance remain outside the local handoff.

These gaps are kept visible rather than labelled as passed milestones. Public hosting and anything paid remain deferred under the user's instruction.
